# Lot 12 — La bascule — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `flw.sh` sert la V2 à la racine, pour tous, sans casser un seul lien, page légale ou calendrier intégré de la V1.

**Architecture:** la V2 passe en `base: '/'` et se déploie sur le site Netlify qui porte `flw.sh`
(`fellowship-app`). Son `netlify.toml` reprend les en-têtes de la V1 et ajoute les 301 des anciens
liens. Les quatre absents de la V2 (légal, embed, `/e/:slug`, vitrine sans compte) y sont portés. Le
service worker de la V2 nettoie une fois la V1 ; un `version.json` fait apparaître « Recharger ».

**Tech Stack:** React 19, React Router, Vite, Vitest, Netlify CLI, Supabase edge functions (Deno).

**Spec:** `docs/superpowers/specs/2026-10-19-lot-12-bascule-v2-design.md`

## Global Constraints

- Chaque fichier neuf de `apps/web-v2/src` porte l'en-tête `QUOI / POURQUOI / ATTENTION` vérifié par `scripts/check-headers.mjs`.
- TS strict : pas de `any`, `@ts-ignore`, `as unknown as`. Pas de `console.log`.
- Rien de la V1 n'est supprimé (`apps/web` reste tel quel). Aucune migration.
- Aucune adresse `flw.sh/v2`, `/v2/`, ni `flwsh.netlify.app` dans `apps/web-v2/src`, `apps/web-v2/public`, `supabase/functions` (hors doc et endpoint de test Mozilla).
- Textes affichés, mot pour mot : « Une nouvelle version de Fellowship est disponible. » · bouton « Recharger ».
- Écrans sans maquette (pages légales, bandeau, vitrine invitée) : briques et jetons existants, rien d'inventé.
- Commits en Conventional Commits, en français, un par tâche ; fin de message `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- Un lien de parrainage `?r=CODE` qui passe par une 301 (`/v2/?r=…`, `/abonnement?r=…`) garde son code → vérifié par `curl -sI` au déploiement (Tâche 9).
- Un visiteur sans compte sur `/:slug` d'une enseigne qui n'existe pas → même écran « introuvable » qu'un connecté, pas de page blanche (Tâche 5, vérif navigateur).
- Un calendrier intégré d'une enseigne sans date à venir, ou au slug préfixé `@` → rendu V1 identique (Tâche 6, vérif navigateur).
- `version.json` injoignable (hors ligne) ou malformé → aucun bandeau, aucune erreur visible (Tâche 8, test).
- `/e/<slug inconnu>` → même comportement qu'un `/evenement/<id inconnu>` (Tâche 4, vérif navigateur).
